# Schemas

JSON Schemas (draft 2020-12) ship as package data in
`src/blueprint_pipeline/schemas/`. Every persisted document carries
`schema: "blueprint.<name>"` and `schema_version: "MAJOR.MINOR.PATCH"`.

| Name | Version | Written by | Purpose |
|---|---|---|---|
| `source-register` | 1.0.0 | operator | source IDs, relative paths, optional checksums, declared fragment class |
| `relationships` | 1.0.0 | operator | declared pairwise relationships (`asserted_by` HUMAN/HEURISTIC/MODEL) |
| `decisions` | 1.0.0 | operator | placements, merges, revision acceptance, hypotheses |
| `extraction-response` | 1.0.0 | local model | output contract for extraction (unversioned payload) |
| `extraction-record` | 1.0.0 | pipeline | stored extraction with provenance, per-phase status, observations |
| `evidence` | 1.0.0 | pipeline | relationships, origins, families, fragments, identity candidates, conflicts, questions |
| `canonical-model` | 1.0.0 | pipeline | rooms, walls, openings, adjacency, measurements, conflicts, revisions, decisions, questions, unplaced items |
| `review-response` | 1.0.0 | local model | output contract for visual review |
| `review-record` | 1.0.0 | pipeline | stored review bound to an artifact hash |
| `validation-report` | 1.0.0 | pipeline | mechanical checks |
| `legacy-house-model` | 0 | (old scaffold) | input to `blueprint migrate-model` only |

Artifacts also have `*.meta.json` sidecars (`blueprint.artifact-meta` 1.0.0):
artifact SHA-256, input hashes, config hash, model, content schema tag.

## Canonical feature fields

Every room, wall, opening and adjacency carries:
`source_ids`, `evidence_origin_ids`, `raw_observation_ids`, `confidence`,
`placement_state`, `revision_state`, `human_confirmation`, `conflict_refs`,
`hypothetical`, `uncertainty`, `decision_ids`. Normalized values (polygons in
mm, measurement `value_mm`) are stored next to their raw observations
(`raw_text`). Rules enforced by `check_model`:

* geometry requires a placement decision, or `hypothetical: true` with a stated uncertainty;
* `polygon_mm`/`wall_id` present ⇔ placement state is ANCHORED/LIKELY/AMBIGUOUS;
* every non-hypothetical feature has ≥ 1 source and ≥ 1 evidence origin, all registered;
* every conflict reference resolves; units are `mm`; IDs are unique.

## Versioning policy

* **PATCH** — documentation or description changes only.
* **MINOR** — backwards-compatible additions (new optional field, new enum
  value that readers may ignore). Readers accept any MINOR of the same MAJOR.
* **MAJOR** — anything else. Readers refuse a different MAJOR with a message
  pointing at the migration command.

## Adding a schema version

1. Edit `src/blueprint_pipeline/schemas/<name>.schema.json`; update `$id`
   (`urn:blueprint:schema:<name>:<version>`) and `CURRENT_VERSIONS` in
   `schemas/__init__.py`.
2. For a MAJOR change of a stored document, add a function
   `migrate_<name>_<old>_to_<new>(doc) -> doc` in `canonical/migrate.py`,
   register it in `MIGRATIONS`, and expose it through the CLI if operators
   need to run it.
3. Content schema tags (`<name>@<version>`) are part of artifact metadata, so
   existing artifacts become stale automatically and are regenerated by
   `blueprint resume`.
4. Add tests: valid/invalid documents for the new version and the migration.
5. Record the change in `CHANGELOG.md` and `docs/MIGRATION.md`.
